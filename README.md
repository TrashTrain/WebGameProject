# 밤의 수호자 · Night Rampart

> 블록을 지워 수호령을 소환하고, 성벽을 도는 그림자를 막아내는 퍼즐 디펜스.

**▶ [브라우저에서 바로 플레이](https://trashtrain.github.io/WebGameProject/)**

설치 없이 돌아가는 Unity WebGL 게임입니다. PC는 마우스, 모바일은 터치로 같은 조작을 합니다.
**2026 saaskr 게임 어워드** 출품작.

## 한 줄 지우는 맛 + 어디에 세울까

블록 퍼즐과 타워 디펜스는 보통 따로 노는 장르입니다. 이 게임은 둘을 한 판에 묶었습니다 —
**퍼즐이 곧 자원 생산**이고, 그 자원이 성벽을 지킬 병력이 됩니다. 줄을 지우면 수호령이
소환되고, 그 수호령을 어디에 세우느냐가 다음 스테이지를 버틸지 말지를 결정합니다.

## 목표

밤의 성벽을 도는 그림자 무리로부터 버팁니다.

- 체력 **10**으로 시작합니다.
- 적이 성벽을 **한 바퀴 완주하면 체력 1**이 깎입니다.
- 체력이 **0이 되면 끝**입니다.
- **얼마나 깊은 스테이지까지 갔는지**가 점수이자, 다음 판을 위한 재화가 됩니다.

## 하는 방법

1. **블록을 놓습니다.** 아래쪽 격자에 손에 든 블록 3개 중 하나를 끌어다 놓습니다.
2. **줄을 지웁니다.** 가로·세로·**대각선**이 꽉 차면 줄이 빛이 되어 사라지고, 수호령이 소환됩니다.
3. **수호령을 배치합니다.** 성벽 안쪽 **12칸** 중 아무 데나 끌어서 옮깁니다.
   이미 누가 서 있는 칸에 놓으면 **서로 자리를 바꿉니다.**
4. **합성합니다.** 같은 종류·같은 등급 **3마리**가 모이면 한 단계 위로 합쳐집니다.

| 한 번에 지운 줄 | 나오는 수호령 |
|---|---|
| 1줄 | 일반 |
| 2줄 | 희귀 |
| 3줄 | 영웅 |
| 4줄 이상 | **전설** + 남는 줄마다 일반 1마리 |

> 최고 등급인 **신화**는 줄 지우기로는 나오지 않습니다. 합성으로만 닿을 수 있습니다.

**정원은 10마리입니다.** 꽉 찬 상태에서 또 소환되면 그 수호령은 골드로 바뀌고, 화면이 그렇게
알려줍니다. 필요 없는 수호령은 판매해 점수로 바꿀 수 있습니다.

## 수호령 세 종류

같은 등급이라도 하는 일이 다릅니다. 그래서 **"무엇을 모을까"와 "어디에 세울까"가 둘 다
결정**이 됩니다.

| 종류 | 특수 효과 | 사거리 |
|---|---|---|
| **등불** | 맞은 적의 속도를 1.5초간 **40% 깎습니다** | 보통 |
| **방패** | 주변의 적까지 **함께 때립니다** (위력 60%) | **짧습니다** (×0.62) |
| **창** | — | **깁니다** (×1.85) |

- 둔화는 **겹치지 않습니다.** 등불을 여러 마리 세우면 더 센 쪽 하나만 적용됩니다
  (겹치게 두면 적이 멈춰서 판이 끝나지 않습니다).
- 세 종류는 **전설 등급까지 그대로 살아남습니다.** 최고 등급인 **신화**에서만 하나로 합쳐져
  둔화·범위·긴 사거리를 **모두** 가집니다.

## 스테이지가 깊어지면

- **10스테이지마다 격자가 커집니다** — 4×4 → 5×5 → 6×6.
- **6×6이 되면 4칸 블록**이 확률적으로 섞여 나옵니다. 한 번에 많이 채우는 대신 자리를 많이 먹습니다.
- **5스테이지마다 보스**가 옵니다. 보스를 놓치면 남은 체력과 무관하게 **고정 피해**를 받습니다.
- 손에 든 블록 중 **어느 것도 놓을 자리가 없으면** 보드가 정리되고 체력 1을 잃습니다.
  이때도 화면이 이유를 말해 줍니다.

판이 끝나면 도달한 스테이지만큼 재화를 받아, 메인 화면에서 **체력·공격력·공격속도** 같은
영구 강화를 살 수 있습니다.

## 조작

- **블록** — 드래그해서 격자에 놓기
- **수호령** — 드래그해서 이동, 다른 수호령 위에 놓으면 자리 맞바꿈
- **판매** — 판매 버튼 → 수호령 탭(머리 위에 "판매"가 뜸) → 한 번 더 탭하면 판매
- 모바일은 같은 조작을 터치로 합니다.

## 기술

| | |
|---|---|
| 엔진 | Unity **6000.6.9f1** (Unity 6.6), Universal 2D / URP |
| 타깃 | WebGL — Brotli 압축, 데스크톱 + 모바일 브라우저 |
| UI | uGUI + TextMeshPro (쓰는 글자만 구운 정적 SDF 아틀라스) |
| 입력 | Input System — 마우스와 터치 공용 |
| 구조 | 게임 규칙은 엔진에 의존하지 않는 `SummonDefense.Core` 어셈블리로 분리 |
| 테스트 | EditMode **240개** |
| 밸런스 값 | 코드가 아니라 `Assets/Resources/config/run.json` |

규칙을 엔진에서 떼어 놓은 덕에 **에디터를 켜지 않고 전 판을 시뮬레이션**할 수 있습니다.
아래 숫자들이 거기서 나왔습니다.

## 숫자는 추측이 아니라 측정으로

밸런스를 "느낌"으로 정하지 않았습니다. 그리고 측정은 몇 번이나 제 예상을 뒤집었습니다.

- **수호령 정원은 10입니다.** 200판 × 400마리를 돌려 고른 값입니다. 정원 6에서는 400마리 중
  **354마리**가 정원 초과로 버려지고 신화에 **한 번도** 닿지 못했습니다. 10에서는 38마리만
  버려지고 매 판 신화에 닿습니다.
- **방패가 창보다 셀 거라 봤지만 아니었습니다.** 측정은 13 대 13으로 비겼습니다. 그래서
  "어느 쪽이 센가"가 아니라 각자의 쓸모를 나누는 쪽으로 다시 설계했습니다.
- **적을 더 많이, 더 느리게 하면 어려워질 줄 알았는데 오히려 쉬워졌습니다.** 반대로 알고
  있었던 셈입니다.
- **보드 정리는 22수에 한 번** 일어납니다(6×6 + 4칸 블록, 2010수 측정). 생각보다 잦아서,
  "왜 보드가 지워졌는지" 알려주는 문구가 선택이 아니라 필수였습니다.
